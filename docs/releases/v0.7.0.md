# Zigbee Anthema 0.7.0

The first public release. It was tested on one system, Kohler Anthem+; Zigbee2MQTT, ZHA and Hue are untested.

## What a client sees of the rename

The board now presents itself as Zigbee Anthema. For a client that means:

- the mDNS service type is `_zigbee-anthema._tcp`;
- the default name is `Zigbee Anthema <id>`;
- the setup hotspot is `Zigbee-Anthema-<id>`;
- the value that says a client made the change is `"api"`, in `light.by`, `button.release_by` and the
  webhook's `by`;
- the value that says the Zigbee controller made the change is `"zigbee"`, in the same three places;
- the state's object (and the key of its `change` events) that holds what the Zigbee controller has asked for is
  `controller`;
- `POST /light`'s answer inside the 3 s echo window is `"ignored": "controller_command_3s"`;
- the log tags now say API and WEBHOOK.

Three values, one key and the log tags changed; see the compatibility note at the end of
[`docs/protocol.md`](https://github.com/frozenmartini/zigbee-anthema/blob/main/docs/protocol.md) for what boards before 0.7.0 wrote, and accept both if you must work with
both. Nothing else on the wire changed: every URL path and every error code is as before, and so is every other
JSON key but two settings: `blink_ms` is gone and `hue` is new (a `PUT` naming a key the board does not know is
refused whole).

## The update stream

A firmware update now ends cleanly on the event stream. The stream's last change carries `rebooting` and
`version`, then `event: end`, and the board waits 2 s before it restarts (it was 500 ms), so the answer and the
last events reach a client on a weak link.

## The blink is removed

The Shortcut's double blink after a client's release (`blink_ms`) is gone, and so is the setting.

## The colour light

- The NanoC6's colour LED shows the button and the claim: rapid green from 3 s of holding (let go for the setup
  hotspot, then a green double flash while it is up), rapid red from 10 s (the claim is cleared at that moment;
  let go), and a red double flash while no client holds the board. The blue LED stays off.
- `POST /api/v1/identify` takes an optional `rgb=RRGGBB` and shows the light solid in that colour (white
  without it).

## The `hue` setting

New: `hue`, on by default. Off answers Kohler Anthem+'s hue read as unsupported. It applies at the next reboot or
`/zigbee/erase`, and Kohler Anthem+ reads it at its next pairing.

## Identity

The default is neutral: the manufacturer `"Zigbee Anthema"`, the model `"zigbee-anthema"`, the chip's own
address, and one pairing QR for every board (the text `ZigbeeAnthema`; see
[`docs/pairing.md`](https://github.com/frozenmartini/zigbee-anthema/blob/main/docs/pairing.md)). The Sengled E11-N1EA clone is a build option.

## Install

Use the install page, https://frozenmartini.github.io/zigbee-anthema/, or push the application image to a
board that is already running with `POST /api/v1/update` (see the README).
